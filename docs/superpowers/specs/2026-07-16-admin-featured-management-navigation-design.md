# 后台精选管理独立页面设计

## 背景

当前后台顶栏只有“图片库 / 内容设置”。`/admin/settings.html` 同时承载标签、主分类、本期名字、大屏文案和轮播精选，并用“标签 / 主分类 / 站点”三个数据类型标签页切换。标签与主分类属于内容组织，本期文案与轮播属于首页发布编排，把它们放在同一页面导致“内容设置”和“站点”名称含糊，轮播入口也不符合管理员的任务心智。

本设计采用独立的“精选管理”页面，同时把原“内容设置”收敛为“标签与分类”。

## 目标

- 后台顶栏改为“图片库 / 精选管理 / 标签与分类”。
- “精选管理”统一管理本期名字、大屏文案、轮播图片和轮播顺序，并一次保存。
- “标签与分类”只管理标签和主分类，不再加载站点配置或轮播逻辑。
- 保持现有 D1 数据结构、Repository、管理 API 和公开站点行为不变。
- 页面和脚本按任务职责拆分，避免隐藏分支继续混合两套工作流。
- 不查看、下载、解码、截图或分析任何图库图片。

## 信息架构

| 顶栏入口 | 路由 | 职责 |
| --- | --- | --- |
| 图片库 | `/admin/` | 上传、搜索、标签交集筛选、选择与批量管理图片 |
| 精选管理 | `/admin/featured.html` | 编辑本期信息、选择轮播图片、调整顺序并统一保存 |
| 标签与分类 | `/admin/settings.html` | 创建、搜索、重命名、排序标签和主分类 |

三个页面使用相同顺序的顶栏链接，并只给当前入口添加 `is-active`。品牌入口仍指向图片库，“查看前台”和“退出”保持原位置与行为。

## 精选管理页面

新增 `public/admin/featured.html`，页面标题和主标题均使用“精选管理”。页面采用现有安静、工作型后台样式，不增加营销式介绍或装饰卡片。

页面内容分为两个连续的无框区域：

1. 本期信息：保留“本期名字”和“大屏文案”字段及现有长度限制。
2. 轮播精选：保留当前精选列表、“从图片库添加”、上下移动和移除操作。

“保存站点设置”改为“保存精选设置”。本期信息与轮播 ID 继续通过同一个 PATCH 请求原子保存，防止文案与轮播顺序部分生效。状态文案使用“精选设置已修改”“精选设置已保存”等任务语言，不再向用户显示“站点设置”。

轮播候选选择器继续只展示符合共享资格规则的图片，并提供“全部可用”“4K”“2K”“HD+ / 900p+”四个档位。现有 legacy 不合规精选仍可查看和明确移除，不会因打开或确认选择器被静默删除。

## 标签与分类页面

保留路由 `public/admin/settings.html`，避免旧书签失效，但可见名称从“内容设置”改为“标签与分类”。页面只保留“标签”和“主分类”两个标签页以及对应的新增、搜索、排序和编辑操作。

删除“站点”标签页和 `site-panel` DOM。`settings-page.js` 不再导入或创建精选控制器，不再维护 `isSiteTab()`、站点模式分支或站点加载流程。认证后只读取标签和主分类，标签与分类操作保持现有行为。

## 脚本边界

### `featured-page.js`

新增 `public/assets/admin/featured-page.js`，只负责：

- 管理密钥读取、登录、自动登录和退出；
- 创建管理 API client、通知器和对话框宿主；
- 创建、绑定并加载现有精选设置控制器；
- 在请求期间同步登录按钮和精选页面忙碌状态；
- 把 401 统一转换为登录界面。

精选页面不需要标签和主分类数据。有效管理密钥直接通过 `/api/admin/site` 的加载请求验证，避免为了认证额外请求标签和分类。

### `settings-page.js`

现有脚本收敛为纯 taxonomy 页面：

- `activeType` 只允许 `tags` 或 `categories`；
- 删除 `site-settings.js` import 和所有站点模式条件分支；
- 认证仍复用标签响应，并请求一次分类列表；
- 新增、重命名、可见性、删除和排序逻辑保持不变。

### `site-settings.js`

继续作为精选表单与轮播选择器控制器，避免复制已经验证的选择、排序、legacy 保留和原子保存逻辑。内部文件名和 `/api/admin/site` 路径保持兼容，但所有可见“站点设置”文案改为“精选设置”。控制器仍通过传入的 `root` 查找既有字段 ID，因此不需要依赖旧 `site-panel` 名称。

## 数据流

### 精选管理

1. 页面读取本地管理密钥。
2. 控制器请求 `GET /api/admin/site`；成功时显示并填充本期信息与当前精选，401 时清除密钥并显示登录界面。
3. 只有点击“从图片库添加”时才请求 `GET /api/admin/images`，并在浏览器内按共享资格元数据筛选候选。
4. 点击“保存精选设置”时发送现有 `PATCH /api/admin/site`，包含 `issueName`、`heroCopy` 和有序 `featuredImageIds`。
5. 服务端继续使用 Repository 的共享资格规则和原子写入，不新增端点或数据库迁移。

### 标签与分类

1. 登录验证返回标签列表。
2. 页面请求分类列表。
3. 后续操作继续调用现有标签、分类和排序 API。
4. 页面不请求 `/api/admin/site` 或 `/api/admin/images`。

## 认证与错误处理

- 三个后台页面继续使用同一管理密钥存储和 401 清理行为。
- 精选首次加载失败时保留页面框架并通过通知器显示安全错误；无效密钥返回登录界面。
- 打开候选选择器失败时不改变当前草稿。
- 保存失败时保留未保存的本期信息和轮播草稿，便于重试。
- 标签与分类现有错误提示和排序回滚行为不变。

## 路由与兼容性

- `/admin/settings.html` 保留并变成标签与分类页面，不需要重定向。
- 新增 `/admin/featured.html`；所有后台顶栏统一提供该入口。
- 当前没有受支持的“站点”查询参数或独立深链接，因此删除旧站点标签页不会破坏已定义路由契约。
- API、D1、R2、公开页面和 Hero 展示均不改变。

## 缓存策略

使用新的设置前端版本 `20260716-admin-featured-navigation`：

- `settings.html` 引用变更后的 `settings-page.js` 时使用新版本；
- `featured.html` 引用新增 `featured-page.js` 时使用新版本；
- `featured-page.js` 引用变更后的 `site-settings.js` 时使用同一版本；
- 未变更的图片库脚本和设置 CSS 继续使用现有版本，避免无意义缓存失效。

静态契约测试必须证明入口脚本和直接变更依赖版本一致，并证明未变更资产仍保留原版本。

## 可访问性与布局

- 三个页面的导航继续使用 `nav` 和 `aria-label="管理页面"`。
- 标签与分类的两个切换按钮继续使用 tablist/tab 语义，并同步 `aria-selected`。
- 精选字段保留显式 `label`、状态区域保留 `aria-live`，图像候选仍可通过 checkbox 操作。
- 固定工具栏、按钮和文字不得在移动端重叠或溢出。
- 本次沿用现有 CSS 组件，不新增卡片嵌套或视觉主题。

## 测试与验收

实施采用测试驱动，至少覆盖：

- 三个 HTML 页面都具有相同顺序的三项顶栏，并正确标记当前入口。
- `featured.html` 只包含本期信息和轮播精选控件，不包含标签或主分类管理 DOM。
- `settings.html` 只包含标签和主分类，不包含站点标签、精选字段或轮播列表。
- `settings-page.js` 不再导入精选控制器，不含站点模式分支，也不请求站点 API。
- `featured-page.js` 只加载精选配置，具备登录、自动登录、退出、401 和安全错误处理契约。
- `site-settings.js` 使用“精选设置”可见文案，选择、排序、跨档勾选和 legacy 保留测试继续通过。
- 定向缓存版本链正确，未变更资产版本保持不变。
- 变更 JavaScript 通过 `node --check`，全量 `npm test` 通过，Git 差异不包含 migration、schema 或 Wrangler 配置。

所有验收只使用合成元数据、静态 HTML/JavaScript 检查和内存数据库。不得启动会下载图片的页面验收，不得请求图片 URL，也不得创建或分析截图。

## 非目标

- 不修改前台 Hero、轮播视觉样式或图片资格规则。
- 不修改 D1 schema、migration、Repository 或 API 数据格式。
- 不把轮播筛选重新放回图片库。
- 不新增角色权限、草稿发布、定时发布或版本历史。
- 不清理或合并与本任务无关的现有工作树和用户文件。
