# 精选图片尺寸资格与固定轮播设计

日期：2026-07-15
状态：已实施并验证

> 后续管理端筛选入口与分辨率档位由 `2026-07-15-admin-featured-filter-separation-design.md` 调整；本文的尺寸来源、最低资格、服务端保存校验与 Hero 布局继续有效。

## 目标

- Hero 轮播区域在所有响应式宽度下保持 `16:9`。
- 轮播图片完整显示，不再因 `object-fit: cover` 裁切。
- 只有精确 `16:9` 且不低于 `1920×1080` 的图片可加入精选。
- 精确 `3840×2160` 的图片额外标记为“4K”。
- 管理端图片库能够直接识别并筛选“轮播可用”和“4K”图片。
- 现有不合规精选由用户手动移除；代码不自动写入或清理生产 D1。

## 宽高元数据来源

沿用现有上传链路：

1. 管理端选择本地文件后，优先使用 `createImageBitmap(file)` 获取解码后的宽高。
2. 若不可用，回退到浏览器图片元素的 `naturalWidth` / `naturalHeight`。
3. 上传初始化和上传完成请求携带宽高；服务端只接受正整数。
4. R2 `head` 确认对象存在后，宽高写入 D1 `images.width`、`images.height`。
5. 后续资格判断只使用 D1 中保存的宽高，不在打开图库时重新下载原图测量。

该方案适配现有无构建、浏览器直传 R2 的架构。管理密钥持有者理论上能伪造上传完成请求中的宽高，但其本来拥有完整图片管理权限；精选资格属于可信管理工作流，而不是安全边界。若未来需要对不可信上传者开放，可再增加服务端图片头解析。

## 单一分类规则

新增服务端共享纯函数，根据 D1 图片记录返回：

- `dimensions`：有效时为 `宽×高`，否则为“尺寸未知”；
- `isExactSixteenNine`：使用整数交叉计算 `width × 9 === height × 16`；
- `meetsMinimum`：`width >= 1920 && height >= 1080`；
- `eligible`：比例与最低分辨率同时满足；
- `is4K`：仅当 `width === 3840 && height === 2160`；
- `reason`：尺寸未知、比例不符、分辨率不足或空值。

示例：

| 尺寸 | 分类 |
|---|---|
| `1920×1080` | Full HD、轮播可用 |
| `2560×1440` | 16:9、轮播可用 |
| `3840×2160` | 4K、轮播可用 |
| `7680×4320` | 16:9、轮播可用（不是“4K”标签） |
| `1280×720` | 分辨率不足、禁选 |
| `1920×1200` | 比例不符、禁选 |
| 空宽高 | 尺寸未知、禁选 |

## API 与服务端约束

- 管理图片 API 在每条图片记录中返回嵌套的 `featuredEligibility`，管理端不重复实现比例算法。
- `updateSiteConfiguration()` 和 `setFeaturedImages()` 在写入 `featured_images` 前查询所有目标图片的 `id,width,height`，使用同一分类函数验证。
- 任意图片未知、不存在或不合规时，整个操作失败；站点名称、Hero 文案和精选顺序保持原值。
- 管理 API 返回 400 和可理解的尺寸规则错误。
- 公开 API 不增加管理资格字段，避免扩大前台数据契约。
- 已经存在于 `featured_images` 的旧记录不自动过滤或删除。用户手动移除后，服务端保证后续无法再次加入不合规图片。

## 管理端图片库

- 卡片显示实际尺寸。
- 合规图片显示“轮播可用”；精确 `3840×2160` 额外显示“4K”。
- 不合规图片显示“比例不符”“分辨率不足”或“尺寸未知”。
- 筛选栏增加互斥快捷筛选：全部、轮播可用、4K。
- 图片详情抽屉显示完整尺寸和资格说明。
- 现有搜索、标签交集、排序、分页和选择状态继续组合生效。

## 精选选择器与当前精选

- 选择器显示所有图库图片及尺寸状态，便于理解为何不可选。
- 不合规图片的复选框禁用，不能作为新精选加入。
- 当前精选列表若含旧的不合规图片，保留条目并显示警告及“移除”操作；不静默删除。
- 新增选择合并时只追加服务端标记为合规的图片，保留既有顺序。
- 保存时服务端再次验证，防止绕过管理界面。

## Hero 布局

- `.hero-stage` 使用 `aspect-ratio: 16 / 9`，宽度继续响应容器。
- 移除桌面 `52vh/520px` 和移动端 `42vh/360px` 的固定高度规则。
- `.hero-image` 填充 16:9 舞台并使用 `object-fit: contain; object-position: center`。
- 合规图片与舞台比例相同，因此正常情况下无裁切也无留白；旧的不合规精选在用户移除前也会完整显示，只可能出现深色留白。
- 透明文字层与轮播控制层继续保持现有层级和移动端间距。
