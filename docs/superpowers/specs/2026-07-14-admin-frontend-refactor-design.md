# Gallery 管理端前端重构设计

日期：2026-07-14

## 1. 背景

当前管理端使用原生 HTML、CSS 和 JavaScript，并部署到无需构建步骤的 Cloudflare Pages。现有实现同时存在四个旧管理页面、正在合并的图片工作台、体积过大的 `admin.js`、混入公开画廊样式的管理 CSS，以及独立维护分类功能的 `admin-categories.js`。这导致页面入口、状态管理和样式职责重复。

本次重构以管理端为主，同时整理前端代码结构。公开画廊的业务和页面布局不在本次改版范围内，但管理端继续使用公开画廊的米白、陶土色设计语言。

## 2. 目标

- 保留所有现有管理能力，业务功能不得回退。
- 提高图片搜索、筛选、上传、详情编辑和批量操作效率。
- 将管理端收敛为图片工作台和内容设置两个页面。
- 拆分脚本、样式和模板职责，保持无构建部署方式。
- 提供完整的加载、空数据、错误和部分失败状态。
- 桌面端优先，同时保证移动端可以完成全部管理操作。

## 3. 非目标

- 不迁移到 React、Vue 或其他前端框架。
- 不引入 Vite、Webpack 或新的生产构建步骤。
- 不重做公开画廊。
- 不改变图片浏览 API、R2 直传和文件访问的总体架构。
- 不实现多用户、角色权限或服务端登录会话。

## 4. 页面与路由

### 4.1 图片工作台

`/admin/` 是唯一的图片工作台，包含：

- 文件名和标签搜索
- 主分类筛选
- 多标签全部匹配筛选
- 排序和图片密度切换
- 图片网格和分批渲染
- 单张图片详情编辑
- 多选、批量标签、批量移动分类和批量删除
- 图片上传任务

### 4.2 内容设置

`/admin/settings.html` 管理标签和主分类，使用两个分段视图。标签支持新增、重命名、排序、显示状态调整和删除；主分类支持新增、重命名和排序，英文目录创建后保持不可修改。

### 4.3 删除旧入口

直接删除以下文件，不保留重定向：

- `public/admin/upload.html`
- `public/admin/images.html`
- `public/admin/tags.html`
- `public/assets/admin-categories.js`

项目仅由单一管理员使用，不需要兼容旧书签和外部入口。相关样式、脚本分支和测试一并删除。

## 5. 登录门禁

不新增 `/admin/login.html`。`/admin/` 和 `/admin/settings.html` 各自在启动阶段显示同一套全屏密钥验证界面。

1. 页面从 `localStorage` 读取管理密钥。
2. 存在密钥时请求 `GET /api/admin/tags` 验证，并复用返回的标签作为当前页面初始数据。
3. 验证成功后才显示管理页面并加载页面数据。
4. 验证失败或任意管理请求返回 `401` 时，立即清除密钥并返回验证界面。
5. 登录成功后停留在用户原本访问的页面。
6. 顶部导航提供“退出”，用于清除密钥和页面状态。

密钥继续通过 `x-gallery-admin-key` 请求头发送。采用 `localStorage` 是本项目单人、受控设备使用场景下的明确取舍。

## 6. 视觉与布局

### 6.1 设计语言

- 延续公开画廊的米白背景、暖白工作面和陶土色主操作色。
- 管理工具保持安静、紧凑，以图片内容为第一视觉层级。
- 卡片圆角不超过 8px，页面区块不使用嵌套卡片。
- 成功、警告和危险状态使用独立的绿、琥珀和红色，不用单一陶土色表达所有状态。

### 6.2 全局导航

顶部栏包含 Gallery 管理标识、图片库/内容设置导航、查看前台和退出操作。仅有两个主页面，不增加永久侧边导航。

### 6.3 图片工作台

- 顶部命令区包含页面标题、图片数量、搜索、排序、密度切换和上传按钮。
- 桌面端左侧固定筛选栏显示主分类、标签搜索和多选标签。
- 右侧为自适应图片网格，显示缩略图、文件名、分类和少量标签。
- 点击图片打开右侧详情抽屉。
- 选择图片后显示固定在视口底部的批量操作条。
- 上传使用居中任务对话框，不占用固定页面区域。
- 成功反馈使用短暂 Toast，不保留常驻状态横幅。

### 6.4 内容设置

- 标签和主分类使用分段控件切换。
- 每个条目显示为边界清晰的独立操作块。
- 新增和重命名使用小型对话框。
- 标签隐藏/显示更新当前条目状态，标签删除必须二次确认。
- 主分类不提供隐藏和删除，以避免引入图片归属迁移和目录清理语义。
- 排序变更先保存在页面草稿，统一点击“保存排序”提交。

## 7. Edge 式跟随排序

标签和主分类共用同一排序组件。交互参考 Edge/Chromium 标签栏，而不是 HTML5 原生拖放或两项直接交换。

### 7.1 行为

- 使用 Pointer Events 捕获鼠标和触控输入。
- 指针移动超过 4px 后才启动拖动，避免点击误触。
- 被拖动条目持续跟随指针，不显示浏览器默认拖动影像。
- 当拖动位置越过相邻槽位的中心阈值时，更新草稿顺序。
- 其他条目使用约 110ms 的 `transform` 动画移动到新槽位。
- 拖回原位置时，条目连续恢复到拖动前的排列。
- 松开指针只结束当前拖动，仍需点击“保存排序”提交。
- `Esc`、`pointercancel` 或异常失去指针捕获时恢复本次拖动开始前的顺序。
- 上移/下移图标按钮提供键盘可操作的替代方式。
- `prefers-reduced-motion` 下取消让位动画，但排序逻辑保持不变。

### 7.2 实现约束

- 排序期间只更新 `transform`，不反复插入文字占位元素。
- 非拖动条目使用稳定槽位，避免布局抖动和拖动目标闪烁。
- 指针移动只更新页面草稿，不发送 API 请求。

参考资料：

- Chromium `TabDragController::MoveAttached`：拖动位置、水平阈值、模型移动和理想位置布局。
- Nielsen Norman Group《Drag-and-Drop: How to Design for Ease of Use》：松开前显示背景对象让位，并使用约 100ms 的短动画。

## 8. 前端模块结构

保持 ES Modules 和无构建部署。目标结构如下：

```text
public/assets/admin/
  api-client.js
  auth.js
  dialogs.js
  notifications.js
  sortable-list.js
  upload.js
  library-state.js
  library-page.js
  settings-state.js
  settings-page.js
  renderers/
    image-card.js
    taxonomy-item.js
```

职责约束：

- `api-client.js` 统一请求头、JSON 解析、超时和 `401` 处理。
- `auth.js` 负责本地密钥、验证界面和退出。
- 页面模块只管理本页面状态和事件绑定。
- `sortable-list.js` 只处理排序交互，通过回调读取和提交顺序。
- 渲染器返回页面所需 DOM/HTML，不包含 API 请求。
- 公开画廊模板不再承载管理端图片和标签模板。

## 9. 样式结构

`main.css` 回归公开画廊专用。管理端样式拆为：

```text
public/assets/admin/admin.css
public/assets/admin/workbench.css
public/assets/admin/settings.css
```

- `admin.css` 定义管理端令牌、基础控件、登录、顶部导航、对话框、抽屉、Toast 和状态样式。
- `workbench.css` 定义筛选栏、图片网格、批量工具和上传任务。
- `settings.css` 定义分段控件、内容条目和排序状态。
- 删除 `main.css` 中重复的管理端覆盖规则。

## 10. 数据流

### 10.1 启动

1. 启动认证模块。
2. 验证本地密钥。
3. 验证成功后按页面并行读取所需数据。
4. 页面进入加载、成功、空数据或错误状态。

图片工作台维护图片、标签、分类、查询、筛选、排序、选择集合和渲染上限。内容设置页分别维护服务器顺序、草稿顺序和脏状态。

### 10.2 上传

- 保留浏览器直传 R2。
- 保留分批上传，避免一次并发所有文件。
- 上传对话框逐项展示等待、上传中、成功和失败。
- 失败文件可单独重试，不重复上传成功文件。
- 上传完成后更新图片工作台数据和数量。

### 10.3 批量排序接口

标签和分类分别增加 `PATCH /api/admin/tags/reorder` 与 `PATCH /api/admin/categories/reorder`。请求提交完整、连续的新顺序：

```json
{
  "items": [
    { "id": 3, "sortOrder": 1 },
    { "id": 8, "sortOrder": 2 }
  ]
}
```

服务端校验 ID 唯一、排序值连续且所有条目存在，再使用 D1 批量写入。任一校验或写入失败时整个请求失败，避免部分排序落库。

## 11. 错误与反馈

- 输入错误显示在对应字段下方。
- 请求期间只禁用相关操作，不冻结无关页面区域。
- 成功操作使用短暂 Toast。
- 页面请求失败显示保留上下文的错误状态和重试按钮。
- 上传错误显示在具体文件旁，并提供失败项重试。
- 删除和批量删除使用应用内确认对话框。
- `401` 是唯一会清空整个管理状态并返回登录门禁的请求错误。
- 对话框、抽屉关闭后恢复触发控件焦点。

## 12. 响应式与可访问性

- `>= 1100px`：固定筛选栏和图片网格并列。
- 中等宽度：筛选栏变为可开合侧栏。
- 手机端：单列图片列表、底部批量操作区、全屏上传和详情层。
- 所有功能在手机端均可完成，但桌面端是主要效率目标。
- 图片使用懒加载，图片网格继续分批渲染。
- 图标按钮提供 `aria-label` 和悬停提示。
- 动态状态通过 `aria-live` 公布。
- 对话框和抽屉实现焦点约束、`Esc` 关闭和焦点恢复。
- 固定格式控件使用稳定尺寸，动态内容不得推动工具栏或图片网格跳动。

## 13. 测试

### 13.1 单元测试

- 管理密钥读取、保存、清除和验证失败流程。
- API 客户端的请求头、JSON 错误、超时和 `401` 行为。
- 排序的 4px 启动阈值、中点换位、连续反向恢复、取消和保存。
- 图片搜索、多标签全部匹配、分类筛选和选择集合。
- 上传参数、分批处理、部分失败和失败项重试。

### 13.2 API 和仓储测试

- 标签和分类批量排序的输入校验。
- 缺失 ID、重复 ID、重复排序和非连续排序拒绝。
- D1 批量写入成功和失败时的原子行为。

### 13.3 模板与浏览器验收

- `/admin/` 和 `/admin/settings.html` 存在并加载正确入口模块。
- 三个旧页面和 `admin-categories.js` 不再存在。
- 验证、退出、搜索、筛选、上传、详情、批量操作、排序和标签删除流程可用。
- 桌面、平板和手机视口无重叠、溢出或不可操作控件。
- 拖动排序无闪烁，拖动项跟随指针，背景项平滑让位。
- 运行完整 `npm test`。

## 14. 完成标准

- 所有现有管理能力在新页面中可用。
- 管理端只保留图片工作台和内容设置两个入口。
- 管理脚本、模板和样式按职责拆分。
- 登录前不显示管理主体，也不加载管理数据。
- Edge 式排序在鼠标、触控、键盘和减少动画设置下均可用。
- 加载、空数据、错误、上传部分失败和无效密钥状态完整。
- 自动测试和浏览器验收通过。
