# Gallery 发布安全修复设计

日期：2026-07-14
状态：已实施并完成本地验收
范围：修复 Hero 精选与公开站点改动；发布前不直接修改生产 D1/R2

## 1. 目标

在保留现有「轻品牌 Hero + 手动精选 + 当前一期」产品范围的前提下，消除当前工作区中会阻碍安全提交和部署的问题：

- 全量 CI 恢复通过
- 站点设置更新不存在部分写入
- Hero 增强失败不会拖垮标签画廊
- 自动轮播可暂停，并尊重用户的减少动态效果偏好
- 精选选择器不会无意重排已有顺序
- 公开 API 不再显式返回后台文件名字段
- 本地演示资源不会被误部署
- GitHub 同步流程不再使用强推
- 新增行为具备无需第三方依赖的回归测试

## 2. 非目标

- 不实现多期图集、往期归档或自动精选
- 不引入完整前端测试框架或第三方 DOM 环境
- 不重构整个 Repository、迁移体系或管理端架构
- 不变更 Cloudflare 绑定、生产数据、密钥或部署配置
- 不执行 Git 提交、推送或 Cloudflare 部署

## 3. 后端设计

### 3.1 严格请求校验

管理端站点 PATCH 在任何数据库写入前完成全部校验：

- `issueName` 和 `heroCopy` 若出现，必须是去除首尾空白后的非空字符串
- `featuredImageIds` 若出现，必须是数组
- 数组元素必须全部为正整数，不接受静默丢弃无效值
- 重复 ID 视为无效请求，避免客户端错误被悄悄纠正
- 空数组是合法值，表示清空精选
- 所有图片 ID 必须在 `images` 表中存在

### 3.2 原子站点更新

Repository 新增一个面向用例的原子更新方法，同时处理站点文案和精选列表。该方法先完成校验和图片存在性检查，再把以下操作放入同一原子单元：

1. 按需 upsert `issue_name`
2. 按需 upsert `hero_copy`
3. 当请求包含精选列表时，替换 `featured_images`

Cloudflare D1 使用 `database.batch()` 提交准备好的语句；Node `DatabaseSync` 测试适配器使用显式事务并在异常时回滚。任何失败都不得留下文案已保存、精选未保存的中间状态。

现有 `updateSiteSettings()` 和 `setFeaturedImages()` 可继续服务单一操作和既有测试；API 改为调用新的原子方法。

### 3.3 公开与管理序列化分离

新增明确的公开图片序列化函数。公开图片只返回：

- `id`
- `fileUrl`
- `width`
- `height`
- `tags`

管理端序列化继续返回 `fileName`、分类、同步状态和备注。文件 URL 本身可能仍含存储文件名，因此此修复保证的是“不再额外暴露后台字段”，不承诺 URL 匿名化。

## 4. 前台设计

### 4.1 独立数据加载与降级

把公开数据加载提取为无 DOM 依赖的小模块，并允许注入 `fetch` 以便测试：

- 标签请求是核心请求；失败时保留现有统一错误状态
- 站点配置请求与标签请求并发执行
- 站点配置失败时返回本地默认配置和空精选，不影响标签及图片浏览
- 非 JSON、404、500 和网络异常均走同一站点降级路径

### 4.2 可测试的轮播状态机

把轮播索引、计时器和暂停原因提取为纯状态控制器。DOM 层只负责渲染和转发事件。控制器支持：

- 下一张、上一张、点选指定图片
- 手动暂停/继续
- 悬停暂停
- 键盘焦点进入 Hero 时暂停
- 页面不可见时暂停
- `prefers-reduced-motion: reduce` 时默认不自动轮播
- 少于两张精选时不创建计时器
- 手动切换后重新计算是否应启动计时器

Hero 控制区增加一个可见的“暂停轮播/继续轮播”按钮。按钮文字和 `aria-pressed` 与状态同步；减少动态效果用户仍可手动切换图片。

### 4.3 精选选择器顺序

确认选择后：

1. 保留仍被勾选的已有精选及其当前顺序
2. 删除被取消勾选的已有精选
3. 按图片库顺序把新勾选图片追加到末尾

这样“从图片库添加”不会破坏管理员已经调整好的轮播顺序。

## 5. 本地工具与同步安全

- `.gitignore` 增加 `public/demo/`；种子脚本仍可在本地生成并由本地静态服务访问
- 种子脚本用实际文件大小选择 SQLite 数据文件，不再比较路径字符串长度
- `sync-github.cmd` 改为普通 `git push -u origin main`
- 仓库同步文档改为当前事实：本地与远端基线一致，新功能位于未提交工作区；普通推送的非快进保护应保留
- 不自动暂存任何文件，避免把演示资源或无关改动混入提交

## 6. 测试设计

### 6.1 先失败的回归测试

- 模板测试使用与 `fileName` 不同的 `fileUrl`，只验证文件名字段没有进入可见/无障碍文案
- API 组合更新包含未知图片 ID 时返回 400，且期名、文案、精选列表全部保持原值
- 非整数或重复精选 ID 返回 400，不会清空当前精选
- 公开 API 响应不包含 `fileName` 和分类字段
- 站点请求失败时，公开数据加载仍返回标签和默认 Hero
- 轮播状态机覆盖启动、切换、各种暂停原因、减少动态效果和销毁
- 选择器顺序逻辑覆盖保留、删除和追加
- HTML 静态契约覆盖轮播暂停按钮

### 6.2 完成门槛

- `npm test` 全量零失败
- 新增和修改的 JavaScript 文件通过 `node --check`
- `git diff --check` 无空白错误
- `git status` 只包含预期的用户原有改动与本次修复
- 不启动生产部署，不写入生产 D1/R2

## 7. 错误处理与兼容性

- 管理端继续使用现有 JSON 错误格式和鉴权方式
- 原子更新的校验错误返回 400；未知运行时错误保留 500 行为
- 站点配置降级只影响 Hero，不隐藏核心错误或标签请求失败
- 不增加运行时依赖，继续支持当前 Node 22 CI 与 Cloudflare Pages Functions

## 8. 实施顺序

1. 为已确认问题补充失败测试
2. 实现 Repository 原子更新与严格 API 校验
3. 分离公开序列化
4. 提取公开数据加载和轮播状态控制器
5. 接入 Hero 暂停交互与选择器顺序修复
6. 修复演示资源、种子脚本和 GitHub 同步流程
7. 更新相关文档并执行完整验证
