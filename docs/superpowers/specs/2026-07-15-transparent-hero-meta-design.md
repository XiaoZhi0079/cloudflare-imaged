# Hero 文案透明叠加设计

日期：2026-07-15
状态：已实施并验证

## 问题

有精选图片时，「本期名字 + 大屏文案」仍处在白色面板中，视觉上遮挡并割裂轮播图片。目标是保留文字信息，但完全移除白色文本框。

## 设计

- 有精选图片时，为 Hero 根节点增加 `has-featured` 状态类。
- `has-featured` 状态下，文案区绝对定位到图片左下方，并位于轮播控制区上方。
- 文案区背景完全透明，不使用白底、半透明渐变、边框或毛玻璃。
- 本期名字和文案改为浅色文字，仅使用轻微文字阴影保证可读性。
- 文案区不接收指针事件，轮播按钮继续保持更高层级和完整点击区域。
- 无精选图片时移除 `has-featured`，文案继续使用现有普通文档流布局。
- 移动端缩小内边距并保持文案位于控制区上方，不产生页面横向溢出。

## 状态流

`renderHero(site)` 根据精选图片数量切换 `siteHero.classList.toggle("has-featured", count > 0)`。CSS 只根据该状态改变布局，不修改 API、轮播状态机或数据结构。

## 验证

- 先增加失败测试，要求运行时代码正确切换 `has-featured`。
- 静态 CSS 测试要求精选态文案区为绝对定位且背景透明，并具有文字阴影和非交互属性。
- 运行完整测试套件，确认无精选、单图、多图及管理端行为不回归。
- 使用浏览器 DOM 与 `getComputedStyle` 检查背景透明、层级、位置和移动端溢出；不截图、不读取或分析图片像素。

## 非目标

- 不修改用户图片、精选顺序、站点文案内容或生产数据。
- 不增加渐变遮罩、模糊背景或新的图片处理逻辑。
- 未经用户单独许可，不查看任何截图或图片内容。
