# 精选配置加载失败保护设计

日期：2026-07-16

## 背景与根因

独立精选管理页通过 `GET /api/admin/site` 验证管理密钥并载入本期文案与有序精选列表。当前非鉴权异常路径会继续显示页面，但控制器初始草稿的 `featuredImages` 为空，HTML 中保存按钮又默认可用。管理员若在加载失败后填写文案并保存，`PATCH /api/admin/site` 会携带空的 `featuredImageIds`，可能清空生产轮播。

根因不是服务端原子性或 D1，而是前端把“页面可见”误当成“配置已成功初始化”，缺少独立的就绪状态。

## 方案比较

1. **失败后退回登录页**：改动最小且安全，但把有效密钥与临时网络故障混为一谈，重试体验差。
2. **自动重试后继续显示空表单**：可以缓解短暂故障，但最终失败时仍必须解决误操作，不能单独构成保护。
3. **页面保留但锁定，显式重试，加载成功后解锁**：能区分鉴权失败和服务异常，既保留页面框架，又从结构上阻止未初始化数据被保存。

采用方案 3，并在保存函数入口增加就绪状态校验作为第二层保护。

## 状态与界面

精选控制器维护两个独立状态：

- `ready`：是否至少成功应用过一次站点配置；初始为 `false`。
- `busy`：是否正在加载、打开候选或保存。

控件规则：

- `ready === false` 时，本期名字、大屏文案、从图片库添加和保存全部禁用。
- `busy === true` 时，上述控件保持禁用。
- 只有 `ready === true && busy === false` 时允许编辑和选图；保存仍需满足草稿已修改。
- HTML 初始态也使用 `disabled`，避免模块加载前短暂出现可操作按钮。

精选页新增隐藏的“重新加载”按钮：

- 首次加载成功：隐藏重试按钮，显示已载入配置。
- 非鉴权异常：显示页面框架和安全错误通知，保持控制器锁定，显示重试按钮。
- 点击重试：暂时禁用重试按钮，再次请求站点配置；成功后隐藏按钮并解锁表单，失败则继续锁定。
- 401：沿用现有逻辑清除密钥并返回登录界面，不显示应用内重试状态。
- 重试进行中暂时禁用退出；每次认证或重试使用递增 attempt ID，退出会使未完成请求的后续 UI 结果失效。

## 数据安全

- `load()` 只有在完整响应成功后才调用 `applyPayload()` 并把 `ready` 设为 `true`。
- 加载失败不会修改服务端快照、草稿或发出 PATCH。
- `save()` 在 `ready === false` 时直接返回并显示安全提示，即使事件被程序化触发也不能请求保存 API。
- 重试不读取图片库；仍只有用户点击“从图片库添加”后才请求 `/api/admin/images`。
- 不修改 API、Repository、D1、migration、公开页面或图片资格规则。

## 测试

使用最小伪 DOM 和伪客户端直接测试真实 `createSiteSettingsController()`：

- 控制器初始控件锁定。
- `load()` 拒绝后控件继续锁定。
- 加载失败后程序化触发保存不会产生 PATCH 请求。
- 后续重试成功会应用服务端配置并解锁编辑/选图；未修改时保存仍禁用。
- 精选入口包含重试按钮和失败/成功切换逻辑。
- 退出后未完成的旧重试结果不能重新显示应用。

定向测试、变更 JavaScript 语法检查和全量 `npm test` 必须通过。验收只使用合成数据与静态 DOM，不访问、下载、解码、截图或分析图库图片。

## 缓存

精选 HTML、`featured-page.js` 和 `site-settings.js` 都发生变化，三者统一升级到缓存版本 `20260716-featured-load-guard`。未变化的设置 CSS、图片库脚本和标签分类入口保持现有版本。
