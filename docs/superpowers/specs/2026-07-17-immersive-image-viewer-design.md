# 前台沉浸式图片浏览器设计

## 目标

在不查看、下载、解码或分析任何图库图片的前提下，为首页标签图库与图集详情页提供一致的沉浸式大图浏览体验。现有图片仍完整显示，文件名和标签继续以透明文字覆盖在图片内部。

## 共享架构

- 新增 `public/assets/image-viewer.js`，集中处理当前图片、上一张/下一张、键盘、触摸滑动、URL/history、相邻图片预加载和弹窗生命周期。
- `gallery.js` 与 `album-page.js` 只负责加载各自的数据、渲染卡片，并把当前图片数组交给共享浏览器。
- 两个页面使用完全相同的查看器 DOM 契约，避免功能继续分叉。
- 共享模块导出无 DOM 的 URL、索引和滑动判断函数，使核心行为可由 Node 测试直接验证。

## 浏览行为

- 单击图片打开居中的大图；文件名显示为主文字，标签显示为次文字，文字背景保持完全透明。
- 查看器提供上一张、下一张和“当前序号 / 总数”计数器；多张图片首尾循环，单张图片隐藏导航按钮。
- 查看器打开时，左右方向键切换图片，Escape 关闭；未打开时不拦截这些按键。
- 触摸手势仅在单指、横向位移占主导且达到 48px 时触发；向左滑看下一张，向右滑看上一张。
- 打开图片后预加载相邻图片，同一 URL 在当前查看器实例中只预加载一次。
- 关闭按钮、点击遮罩和 Escape 均使用同一关闭流程；关闭后焦点回到触发按钮，页面保留原滚动位置。

## URL 与浏览器历史

- 首页图片 URL 为 `/?tag=<当前标签>&image=<图片 id>`。
- 图集详情 URL 为 `/album.html?slug=<图集 slug>&image=<图片 id>`。
- 页面内首次打开使用 `history.pushState`，并标记该历史项由查看器创建；上一张/下一张使用 `replaceState`，避免浏览器后退逐张回放。
- 页面内关闭时优先 `history.back()`；`popstate` 收到无 `image` 的 URL 后关闭查看器。
- 首次加载直达 URL 时，在数据加载完成后打开对应图片；关闭这类查看器时使用 `replaceState` 移除 `image`，不会离开当前页面。
- 首页首次加载优先采用 URL 中存在且可见的 `tag`。切换标签时使用 `replaceState` 更新 `tag` 并清除旧 `image`，确保分享链接拥有完整上下文。
- 若 URL 中的图片不属于当前标签或图集，则不打开查看器并移除无效的 `image` 参数；不新增按图片 ID 枚举图库的公共接口。

## DOM 与可访问性

- 对话框使用 `aria-labelledby="modal-title"` 与 `aria-describedby="modal-tags"`。
- 新增 `#modal-prev`、`#modal-next` 和 `#modal-counter`；导航按钮具备中文 `aria-label`。
- 打开查看器时焦点移至关闭按钮，关闭后恢复触发按钮焦点。
- 查看器开启时为根元素增加 `viewer-open`，只禁止背景滚动，不改变页面滚动坐标。

## 测试与隐私验收

- 核心测试覆盖索引循环、URL 参数保留/移除、历史项策略、键盘路由、滑动阈值和相邻预加载去重。
- 静态测试覆盖两页共享模块、DOM 契约、透明文字背景、响应式按钮与统一缓存版本。
- 发布验收只请求 HTML、CSS、JavaScript 和 API JSON 文本，检查状态码、资源版本与代码契约；不请求 `/file/` 图片，不生成或查看截图。

## 验收标准

1. 首页与图集详情页共享同一个查看器实现。
2. 上一张、下一张、左右键、Escape、手机横向滑动均按设计工作。
3. 每张打开的图片都有可复制的上下文直达 URL，浏览器前进/后退能同步查看器。
4. 关闭查看器后页面仍处于原浏览位置，焦点返回触发按钮。
5. 相邻图片得到预加载，且不重复预加载同一 URL。
6. 全部自动化测试通过，线上文本验收通过，过程中未读取任何图库图片内容。
