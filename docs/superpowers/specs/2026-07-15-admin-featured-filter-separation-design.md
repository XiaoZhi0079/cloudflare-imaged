# 后台标签筛选与轮播候选筛选分离设计

日期：2026-07-15
状态：已实施并完成本地验收，待合并与生产发布

## 背景

当前图片库侧栏同时包含“轮播规格”和“标签（全部匹配）”。两组控件虽然可以组合，但承担的是两种不同工作：标签筛选用于整理图库内容，轮播规格用于挑选站点大屏素材。把它们放在同一个页面会让图片管理与站点编排混在一起，也会让“不符合比例”的图片在轮播选择流程中占据空间。

本设计将两种工作流按页面职责拆开，并沿用已经确认的轮播硬约束：图片必须精确为 `16:9`，且不低于 `1920×1080`。

## 目标

- 图片库页面只保留文件名/标签搜索、标签交集筛选、排序、分页和批量操作。
- 轮播候选筛选只出现在“内容设置 → 站点 → 大屏精选”的选择器中。
- 轮播选择器只展示合规图片，不展示“比例不符”“分辨率不足”或“尺寸未知”的图片。
- 合规候选可按“全部可用、4K、2K、1K/1080p”互斥筛选。
- 分辨率档位与轮播资格由服务端共享规则统一计算，浏览器不重复推导像素规则。
- 旧的不合规精选继续显示在“当前精选”列表中，由用户明确移除；打开或确认选择器不会静默删除它们。

## 分辨率档位

所有档位都以“精确 `16:9` 且不低于 `1920×1080`”为前置条件。按解码后写入 D1 的 `width`、`height` 归类：

| 档位 | 条件 | 选择器标签 |
|---|---|---|
| 4K | `width >= 3840 && height >= 2160` | `4K` |
| 2K | 达到 `2560×1440`，但未达到 4K | `2K` |
| 1K/1080p | 达到 `1920×1080`，但未达到 2K | `1K / 1080p` |

因为资格已要求精确 `16:9`，宽高阈值始终同步成立。`7680×4320` 等更高分辨率归入 4K 档，避免新增没有实际筛选价值的 8K 档；`3200×1800` 等介于标准尺寸之间的合规图片归入 2K 档。

共享分类结果新增稳定字段 `resolutionTier`，值为 `"4k"`、`"2k"`、`"1k"` 或 `null`。`qualityLabel` 与档位同步显示；`is4K` 表示属于 4K 档，保留给现有管理端样式和契约使用。

## 图片库页面

从 `public/admin/index.html` 删除“轮播规格”单选组。图库状态不再保存或组合 `featuredFilter`，清空筛选只清空搜索词和标签选择。

图片卡片回到图库管理职责，不再覆盖显示轮播资格、分辨率档位或不合规原因，以免同一信息继续制造第二筛选层。图片详情仍可显示中性的实际宽高元数据，方便排查上传记录；标签编辑、分类、重命名、删除和批量操作保持不变。

标签逻辑完全沿用现状：选择多个标签时必须全部匹配；文件名/标签搜索继续与标签交集筛选组合；排序和分段渲染继续在筛选结果上工作。

## 站点设置中的轮播候选

“从图片库添加”继续打开选择器，但选择器的数据先经过 `eligible === true` 过滤。比例不符、分辨率不足和尺寸未知的普通图库图片不创建 DOM 卡片，也不提供“不可用”筛选项。

选择器顶部提供四个互斥按钮：

- 全部可用：显示全部合规候选；
- 4K：只显示 `resolutionTier === "4k"`；
- 2K：只显示 `resolutionTier === "2k"`；
- 1K / 1080p：只显示 `resolutionTier === "1k"`。

按钮显示各档候选数量，切换只更新候选网格，不重新请求 D1。筛选结果为空时显示明确空状态。候选卡显示实际尺寸和档位，不再显示重复的“轮播可用”文案。

选择状态独立于当前显示档位：切换档位不会丢失已勾选项。确认时只接受合规候选 ID，并保持已有精选的相对顺序；新增图片按图库返回顺序追加。

## 旧精选兼容

服务端不会自动清理生产 `featured_images`。如果当前精选包含旧的不合规图片：

- 它仍显示在当前精选列表并带有移除警告；
- 它不会出现在候选选择器；
- 打开、切换或确认候选筛选不会删除它；
- 用户必须在当前精选列表点击“移除”，再保存站点设置。

这样既满足候选区“不显示比例不符”，也保持现有生产内容不被后台交互意外修改。

## 数据流与边界

```text
管理图片 API
→ 服务端 classifyFeaturedImage(width, height)
→ 返回 eligible + resolutionTier + dimensions
→ 图片库忽略轮播字段，只执行标签筛选
→ 站点选择器先保留 eligible，再按 resolutionTier 筛选
→ 保存时 Repository 再次用同一规则验证全部目标 ID
```

本次不新增表或列，不改变 R2 对象，不需要为分档迁移生产数据。宽高继续来自上传时浏览器解码后的元数据并存入 D1；选择器不会下载原图重新测量。

## 错误处理

- 管理图片请求失败时，选择器保持关闭并显示现有通知。
- API 返回缺少或未知 `resolutionTier` 的图片，即使 `eligible` 被错误标记为真，也不进入任何候选档；共享服务端分类测试防止该契约漂移。
- 保存仍由 Repository 权威校验，绕过前端或使用过期页面无法加入不合规图片。
- 候选为空时不禁用取消操作，也不改变当前精选草稿。

## 测试与验收

- 共享规则测试 1920×1080、2560×1440、3840×2160、7680×4320、介于标准尺寸之间的 16:9 图片，以及比例错误、过小和未知尺寸。
- 图片库状态测试证明只组合搜索与标签交集，不再暴露轮播筛选状态。
- 图片库模板/控制器测试证明没有“轮播规格”控件或轮播资格卡片覆盖层。
- 站点选择器纯函数测试证明先排除不合规图片，再正确划分 4K/2K/1K。
- 选择合并测试证明跨档切换保留选择，并且不可见的旧不合规精选不会被静默删除。
- 静态渲染测试证明候选区没有“比例不符”“分辨率不足”“尺寸未知”卡片。
- 完整 `npm test`、JavaScript 语法检查、`git diff --check` 和本地 Pages smoke test。
- 生产验收只检查接口字段、DOM 控件、候选数量和网络时序；浏览器阻断所有图片请求，不截图、不查看或分析图片内容。

## 非目标

- 不改变普通图库允许上传和展示的图片比例。
- 不自动裁切、放大、转码或补测旧图片。
- 不增加“比例不符”或“全部图片”轮播筛选项。
- 不把标签筛选复制到轮播选择器。
- 不自动修改当前精选顺序、生产 D1 业务记录或 R2 内容。

## 成功标准

- 图片库后台只呈现标签导向的筛选工作流。
- 站点设置的轮播选择器只呈现合规候选，并可独立按三个分辨率档位筛选。
- 任一不合规普通图片在候选 DOM 中均不存在。
- 旧的不合规精选只能由用户明确移除，不会因筛选交互丢失。
- 服务端保存校验、现有标签匹配和前台轮播行为保持有效。

## 实施与本地验收证据（2026-07-16）

- `npm test`：171 项全部通过，0 失败；相对基线变更的 26 个 JavaScript 文件均通过 `node --check`。
- 使用全新隔离本地 D1 写入 6 条合成宽高记录：3 条合规候选分别属于 4K、2K、1K，另 3 条覆盖比例不符、尺寸不足和未知尺寸；没有使用任何真实图片。
- 图片库 DOM 显示 6 张合成记录、0 个轮播筛选/资格控件；两个标签的交集筛选从 2 条收敛为唯一匹配记录。
- 站点 picker 的计数为“全部 3、4K 1、2K 1、1K 1”，候选 DOM 只有 3 条合规记录，不含不合规原因文本。
- 实际执行“4K 勾选 → 2K 勾选 → 切回 4K → 切回 2K”，两档选择均保持；1K 未被意外勾选。
- legacy 不合规精选在确认 picker 后仍保留；服务端拒绝在它仍存在时保存，显式移除后 4K/2K 两项保存返回 200，验证了“不静默删除、必须明确移除”的边界。
- 浏览器在首次导航前拦截所有 `resourceType === "image"` 请求：21 次图片请求被阻断，图片响应为 0，DOM 中所有图片的 `naturalWidth`/`naturalHeight` 均为 0；未截图、未查看或分析图片内容。
- 验收结束后已停止本地服务并删除隔离 D1；未访问或修改生产 D1、R2、标签、精选顺序或图片内容。
