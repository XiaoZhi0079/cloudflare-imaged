# 精选候选分辨率筛选设计

日期：2026-07-17

## 背景与根因

精选管理只允许接近 16:9 且达到最低尺寸的图片加入前台轮播。当前系统虽然已经在“从图片库添加”弹层中提供分辨率筛选，但只定义了 `4k`、`2k`、`1k` 三档，并把所有低于 2560×1440 的合规图片都归入内部 `1k`；界面又将这一档显示为“HD+ / 900p+”。因此管理员看不到预期的“1K”和“其他”两个独立档位，也无法直观定位 1672×941 等非标准但合规的轮播候选。

这个问题不是 Cloudflare 缓存或图片元数据缺失，而是分辨率分类模型与管理界面的预期不一致。

## 方案比较

1. **按宽、高门槛分成互斥档位**：4K、2K、1K 和其他均采用常见分辨率门槛，非标准尺寸也能落入最接近且不夸大的档位。含义稳定，适合筛选和统计。
2. **只匹配精确标准尺寸**：仅 3840×2160、2560×1440、1920×1080 分别进入对应档位，其余全部归入其他。规则容易解释，但会把 3200×1800 等明显高于 2K 的图片错误地放入“其他”。
3. **按总像素数分档**：对任意尺寸连续分类，但“4K”“2K”“1K”将不再对应管理员熟悉的宽高标准，近似 16:9 图片也可能因舍入落入反直觉档位。

采用方案 1。分档同时检查宽度和高度，避免单边尺寸达到门槛就被高估。

## 资格规则与分辨率档位

分辨率档位只在图片已经满足轮播资格后计算。轮播资格保持不变：

- 图片宽、高元数据均为正整数；
- 宽高比为精确 16:9，或相对 16:9 的误差不超过 0.5%；
- 宽度至少 1600、高度至少 900。

所有合规图片进入且只进入一个档位：

- `4k`：宽度至少 3840 且高度至少 2160，包含 5K、8K 等更高分辨率；界面显示“4K”。
- `2k`：宽度至少 2560 且高度至少 1440，但未达到 4K；界面显示“2K”。
- `1k`：宽度至少 1920 且高度至少 1080，但未达到 2K；界面显示“1K”。
- `other`：满足轮播资格但未达到 1920×1080；界面显示“其他”。1672×941 和 1600×900 属于这一档。

比例不符、低于 1600×900、尺寸未知或尺寸非法的图片继续不进入任何候选档位，也不在候选弹层中显示。

## 管理界面

筛选器位于精选管理的“从图片库添加”候选弹层顶部，只筛选可加入轮播的候选图库，不筛选当前已经选入轮播且需要维护顺序的列表。

候选弹层只显示四个互斥筛选按钮：

- 4K
- 2K
- 1K
- 其他

每个按钮显示该档位候选数量。打开弹层时默认选择 4K；切换档位只改变当前可见候选，不清除其他档位中已经勾选的图片。某档没有候选时显示“当前档位没有可用图片”，四个筛选按钮仍保持可见。

不保留“全部可用”按钮，避免一次加载大量缩略图，并符合只展示四个分辨率筛选器的要求。当前精选列表继续显示图片的实际尺寸和对应档位，以便保存前检查。

## 数据流与实现边界

共享图片资格模块负责唯一的资格判断和档位计算，并在管理员图片接口返回的 `featuredEligibility` 中提供 `resolutionTier` 与 `qualityLabel`。前端只消费该结果，不依据文件名、缩略图或浏览器尺寸重新猜测分辨率。

前端候选控制器需要：

- 接受 `4k`、`2k`、`1k`、`other` 四种合法档位；
- 按选中档位过滤已通过资格判断的图片；
- 将未知档位视为无匹配结果，避免错误输入意外退回全部候选；
- 在跨档位切换时保留勾选集合；
- 保存时继续提交完整、去重且有序的精选图片 ID 列表。

本次不修改 D1 表结构，不回填图片尺寸，不改变图片上传流程、标签筛选、公开页面轮播布局或轮播资格下限。

## 兼容与错误处理

- 已经进入当前精选列表的旧数据仍完整显示；即使旧记录不再合规，也保留现有“移除后再保存”保护，不在加载时静默删除。
- 后端仍在保存时重新验证所有精选图片，前端筛选不能替代服务端校验。
- 管理接口加载失败、未授权和保存失败继续沿用现有锁定、重试与通知逻辑。
- 如果接口返回未知或缺失的档位，图片不会出现在候选弹层，但当前精选列表仍显示实际尺寸和安全的状态提示。

## 测试与验收

共享规则测试覆盖：

- 3840×2160 及更高分辨率进入 4K；
- 2560×1440 和 3200×1800 进入 2K；
- 1920×1080 及达到该门槛但低于 2K 的近似 16:9 图片进入 1K；
- 1672×941、1600×900 进入其他；
- 低于 1600×900、比例超差、尺寸未知和非法尺寸不产生档位。

前端测试覆盖：

- 候选筛选器只包含 4K、2K、1K、其他，不包含“全部可用”或旧的“HD+ / 900p+”；
- 默认激活 4K；
- 四个档位数量正确且筛选结果互斥；
- 切换档位不会丢失已勾选状态；
- 不合规和未知档位图片不会出现在候选中；
- 当前精选顺序、移除操作和保存负载不受筛选影响。

验收使用合成元数据、静态 HTML/JavaScript 检查和自动化测试完成，不访问、下载、解码、截图或分析任何图库图片。完成后更新涉及的静态资源缓存版本，并核对生产返回的 HTML/JavaScript 文本，不进行图片内容验收。
